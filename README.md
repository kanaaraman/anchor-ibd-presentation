# ANCHOR-IBD: Learning Together, Data Stays Home

An interactive, scroll-driven briefing on decentralised **swarm learning** across Swedish and Norwegian IBD registries (Region Östergötland and Örebro on SWIBREG, Oslo University Hospital on NorIBD), running on **NVIDIA DGX Spark** with **NVIDIA FLARE**.

**Code:** [https://github.com/kanaaraman/anchor-ibd-fl-poc](https://github.com/kanaaraman/anchor-ibd-fl-poc): training, NVIDIA FLARE job, DGX Spark deployment, synthetic data generator and validation.

## ▶ Open the presentation

**Live, no install:** https://kanaaraman.github.io/anchor-ibd-presentation/

It works in any modern desktop or mobile browser. Scroll, or use the arrow keys.

## Run locally

It is a single self-contained `index.html` with no build step. Double-click it, or serve the folder:

```bash
python -m http.server 8000
```

Google Fonts load from the internet and fall back to system fonts offline.

## Data and scope

**No real patient data is used.** Every patient is synthetic, generated by code in the [proof-of-concept repository](https://github.com/kanaaraman/anchor-ibd-fl-poc) (see its [DATA.md](https://github.com/kanaaraman/anchor-ibd-fl-poc/blob/main/DATA.md)):

| | |
| --- | --- |
| What exists | One synthetic OMOP CDM extract per hospital (600, 450 and 350 patients) plus 3,000 extra synthetic patients per hospital that are only used to measure results |
| How it is generated | A rule-based generator draws each patient's diagnosis, sex, disease duration, Montreal classification, smoking, prior anti-TNF, co-medication, lab values (CRP, calprotectin, albumin, haemoglobin) and biologic, then clinical remission at week 52 from one formula with effect directions taken from the IBD literature |
| How it is calibrated | Oslo's case mix follows the IBSEN III inception cohort; each drug's remission rate is matched to VARSITY, SEAVUE, ACT 1 or a SWIBREG real-world study |
| How it is validated | A script reads the generated OMOP tables and compares 12 statistics with the published figures: 0 of 9 scored checks passed before calibration, 9 of 9 after. Two IBSEN III figures and the ACT 1 figure are provisional because they come from secondary sources |

The in-browser simulation uses a small logistic model, so its numbers vary with each new cohort. The "Results" and "Rounds and privacy" scenes show the measured numbers from the proof-of-concept code: AUROC 0.743 for each hospital alone, 0.758 for swarm learning and 0.760 with all records copied to one place, on 3,000 new synthetic patients per hospital, averaged over 5 training runs. These numbers show that the federated machinery works on realistic-looking data; they say nothing about real-world predictive performance. The predictions are a research demonstration and must not be used for clinical decisions.

Part of the Vinnova-funded ANCHOR-IBD feasibility project (2026-00990): Region Östergötland, RISE, Örebro University, AbbVie and Oslo University Hospital.
